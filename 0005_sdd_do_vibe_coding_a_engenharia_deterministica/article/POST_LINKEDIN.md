# Post LinkedIn - Do Vibe Coding à Engenharia Determinística usando Spec-Driven Development (SDD) no Claude Code

O seu agente de IA não erra o problema por incapacidade técnica. Ele simplesmente acerta outro problema, o único que estava subentendido no seu pedido vago.

Quando alguém digita no terminal "cria um endpoint que liste as transações do mês", o modelo de linguagem se depara com um vácuo de produto. Mês corrido dos últimos trinta dias? Mês calendário fechado? Mês contábil da organização?

Diante de lacunas como essa, a rede neural não interrompe o fluxo para pedir esclarecimentos. Ela completa o pedido com a continuação estatisticamente mais frequente, toma dezenas de decisões de arquitetura em silêncio e entrega trezentas linhas de código perfeitamente coerentes com uma premissa errada. A equipe descobre a discrepância semanas depois, quase sempre em produção.

Com a facilidade de gerar código a custo próximo de zero no Claude Code, a digitação manual deixou de ser o gargalo da engenharia. O custo de gerar o código errado, porém, continua custando sprints inteiras de retrabalho.

É exatamente por isso que o Spec Driven Development (SDD) se tornou indispensável. No SDD, a hierarquia é invertida: a especificação em texto é a fonte primária da verdade, e o código é apenas um artefato derivado e rigorosamente verificável.

No novo artigo da série Pathbit AI for Devs, detalhamos a esteira completa:

1. A anatomia de uma boa especificação em seis blocos, com critérios de aceite binários no centro
2. O ciclo iterativo em seis fases e o mecanismo de loopback consciente
3. A física da janela de contexto e por que a curadoria enxuta supera prompts gigantescos
4. A sinergia entre SDD e TDD, separando a regra de negócio da validação de código
5. A esteira no Claude Code com CLAUDE.md, slash command /spec, plan mode e subagentes isolados para auditoria independente
6. Estudo de caso completo de uma API de agregador de notícias construída em seis ciclos incrementais

Especificar não é burocracia. É uma forma de explicitar decisões antes da geração; revisão e controle de escopo continuam necessários.
